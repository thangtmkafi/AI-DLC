Ask the agent. Govern the outcome.

Start with a skill command. The agent reconciles the project, confirms your authority, records every clarification, executes the work, and stops at the right human gate.

Yêu cầu agent. Quản trị kết quả.

Bắt đầu bằng skill command. Agent đối soát dự án, xác nhận authority, lưu mọi làm rõ, thực thi công việc và dừng ở đúng human gate.

01 · /kafi-aidlc-onboarding

Join with identity, authority, and context.

Use for a new project or a person joining an existing one.

Tham gia với identity, authority và context.

Dùng cho dự án mới hoặc người mới vào dự án hiện hữu.

Onboard a project or participant

Accountable: PO/PM for project setup; each authority owner confirms project role.

Onboard dự án hoặc người tham gia

Chịu trách nhiệm: PO/PM cho project setup; mỗi authority owner xác nhận role dự án.

INPUT · LOCAL PROFILE + HUB
  1. Run /kafi-aidlc-onboarding. The agent reads the local cross-project user profile and asks the user to confirm name and role. RECORDED
  2. The agent locates the Project Hub and existing state. If no state or operating-model.md exists, it asks guided project questions.
  3. Confirm Entry, Scope, Relationship, Solution Authority, Operating Model, component topology, repository links, and Backstage identifiers.
  4. The agent writes a project-folder conversion plan before restructuring any existing project folder. PO/PM reviews, requests changes if needed, then approves.
  5. The agent records project-scoped authority separately from the local convenience profile and recommends the next valid action.
  1. Chạy /kafi-aidlc-onboarding. Agent đọc profile người dùng dùng chung giữa các dự án rồi yêu cầu xác nhận tên và role. ĐÃ LƯU
  2. Agent tìm Project Hub và state hiện tại. Nếu thiếu state hoặc operating-model.md, agent hỏi các câu hỏi có hướng dẫn.
  3. Xác nhận Entry, Scope, Relationship, Solution Authority, Operating Model, component topology, repository link và Backstage identifier.
  4. Agent viết plan chuyển đổi project folder trước khi tái cấu trúc folder hiện hữu. PO/PM review, yêu cầu sửa nếu cần rồi phê duyệt.
  5. Agent lưu authority trong phạm vi dự án tách khỏi local profile tiện dụng và đề xuất next action hợp lệ.
Evidence or Ask: do not infer identity, authority, project type, vendor boundary, or operating model from job title or folder names.
Evidence or Ask: không suy luận identity, authority, loại dự án, ranh giới vendor hay operating model từ chức danh hoặc tên folder.

Reconcile before resuming.

Status is evidence-backed, not a cached opinion.

Đối soát trước khi tiếp tục.

Status dựa trên bằng chứng, không dựa trên nhận định đã cache.

Resume an existing project

Accountable: current work owner; authority follows the active gate.

Tiếp tục dự án hiện hữu

Chịu trách nhiệm: work owner hiện tại; authority đi theo gate đang active.

OUTPUT · RECONCILED STATUS
  1. Run /kafi-aidlc-status. The agent may safely fetch remote refs but does not merge, checkout, or alter work.
  2. Compare Project Hub and Component Hub state, approved baselines, decisions, questions, work claims, dependencies, Git heads, remote refs, and Backstage topology.
  3. Report active work, blockers, stale evidence, gates waiting for review, unclaimed work, and drift.
  4. Confirm the user profile and project authority if they affect available actions.
  5. Use /kafi-aidlc-next to choose from actions valid for the reconciled state.
  1. Chạy /kafi-aidlc-status. Agent có thể fetch remote refs an toàn nhưng không merge, checkout hay thay đổi work.
  2. So sánh state của Project Hub và Component Hub, baseline đã duyệt, quyết định, câu hỏi, work claim, dependency, Git head, remote ref và Backstage topology.
  3. Báo cáo công việc đang chạy, blocker, bằng chứng cũ, gate chờ review, công việc chưa claim và drift.
  4. Xác nhận user profile và project authority nếu chúng ảnh hưởng các action khả dụng.
  5. Dùng /kafi-aidlc-next để chọn action hợp lệ cho state đã đối soát.
Stop when local and remote evidence conflict. Ask the accountable human which evidence should be corrected; never silently pick one.
Dừng khi bằng chứng local và remote xung đột. Hỏi người chịu trách nhiệm bằng chứng nào cần sửa; không âm thầm tự chọn.
03 · CONFIGURE

Select the operating model from delivery reality.

Continuous is default; Phase-Gated is selected when formal locked baselines and CR governance are required.

Chọn operating model từ thực tế delivery.

Continuous là mặc định; Phase-Gated dùng khi cần baseline khóa chính thức và quản trị bằng CR.

Confirm project profile and model

Accountable: PO/PM; SA confirms technical consequences.

Xác nhận project profile và model

Chịu trách nhiệm: PO/PM; SA xác nhận hệ quả kỹ thuật.

GATE · OPERATING MODEL
  1. Establish whether work flows as independently deliverable slices or as formally locked phases.
  2. Confirm Greenfield/Brownfield, Full-stack/BE-only/FE-only, In-house/Vendor, and KAFI Solution/Vendor Solution.
  3. Show activated and skipped stages before approval. BE-only does not enter UI/UX unless documented impact activates it.
  4. Record the selected model, rationale, authority, and effective timing in Markdown control state.
  5. If changing models, the agent writes a migration plan. It does not convert in-flight work; activation starts at an approved safe boundary.
  1. Xác định công việc chảy theo slice có thể deliver độc lập hay theo phase được khóa chính thức.
  2. Xác nhận Greenfield/Brownfield, Full-stack/BE-only/FE-only, In-house/Vendor và KAFI Solution/Vendor Solution.
  3. Hiển thị stage được kích hoạt và bỏ qua trước khi duyệt. BE-only không vào UI/UX trừ khi impact có bằng chứng kích hoạt.
  4. Lưu model đã chọn, lý do, authority và thời điểm hiệu lực trong Markdown control state.
  5. Nếu đổi model, agent viết migration plan. Không chuyển đổi work đang chạy; activation bắt đầu tại ranh giới an toàn đã duyệt.
Agile/Waterfall may be shown as friendly mappings. The recorded canonical value remains Continuous or Phase-Gated.
Có thể hiển thị Agile/Waterfall như cách gọi thân thiện. Giá trị canonical được lưu vẫn là Continuous hoặc Phase-Gated.
04 · SLICE

Run a Continuous slice.

A slice is bounded, independently reviewable, and traceable across repositories.

Chạy một Continuous slice.

Slice có ranh giới, review độc lập và truy vết được qua nhiều repository.

Deliver SLICE-NN

Discovery: PO/PM. Delivery: SA. Unit quality: Tech Lead.

Delivery SLICE-NN

Discovery: PO/PM. Delivery: SA. Unit quality: Tech Lead.

BRANCH · slice/SLICE-NN
  1. Run /kafi-aidlc-next and select an approved delivery-ready slice or request clarification.
  2. The agent claims the slice in committed Hub state and reconciles all affected component repositories.
  3. Generate a slice plan, activate applicable documents/gates, and obtain the required review before execution.
  4. Execute design, code, automated tests, integration, traceability, and UAT evidence. QA work is agent-led and automation-first; a human QA participates only when the project assigns one.
  5. Human reviewers may request changes repeatedly. After approval, merge the slice contribution set to project mainstream and record the exact revisions.
  6. When slices form an MVP, generate applicable user guide, API specs, operations guidance, release notes, UAT dossier, and SRE handoff evidence.
  1. Chạy /kafi-aidlc-next và chọn slice đã duyệt, sẵn sàng delivery hoặc yêu cầu làm rõ.
  2. Agent claim slice trong Hub state đã commit và đối soát mọi component repository bị ảnh hưởng.
  3. Sinh slice plan, kích hoạt tài liệu/gate áp dụng và nhận review bắt buộc trước khi thực thi.
  4. Thực thi design, code, automated test, integration, traceability và bằng chứng UAT. QA do agent dẫn dắt, ưu tiên automation; human QA chỉ tham gia khi dự án phân công.
  5. Human reviewer có thể yêu cầu sửa nhiều lần. Sau khi duyệt, merge contribution set của slice vào project mainstream và lưu đúng revision.
  6. Khi các slice tạo thành MVP, sinh user guide, API spec, operations guidance, release note, UAT dossier và bằng chứng bàn giao SRE khi áp dụng.
No generic “continue anyway.” A quality exception names the exact failed control, scope, risk owner, expiry, and compensating action.
Không có lựa chọn “cứ tiếp tục” chung chung. Quality exception phải nêu đúng control thất bại, scope, risk owner, thời hạn và hành động bù.
05 · CHANGE REQUEST

Amend a Phase-Gated baseline.

New scope after lock enters through a Change Request.

Amend baseline Phase-Gated.

Scope mới sau khi khóa đi qua Change Request.

Deliver CR-NN

Business authority: PO/PM. Technical impact: SA. Unit approval: Tech Lead.

Delivery CR-NN

Business authority: PO/PM. Technical impact: SA. Unit approval: Tech Lead.

BRANCH · cr/CR-NN
  1. Capture CR intent, source baseline, requested scope, urgency, and acceptance criteria. RECORDED
  2. The agent performs cross-artifact and cross-repository impact analysis, including UI/UX, architecture, API, data, operations, and migration impact.
  3. PO/PM reviews the amendment scope; SA decides technical design and gate activation.
  4. After approval, create the CR branch set, execute affected work, automate tests, and deploy to UAT.
  5. Tech Lead approves Phase-Gated unit quality. PO/PM accepts UAT. SA verifies integration and promotion equivalence.
  6. Promote approved revisions to project mainstream, seal the new baseline, and hand production evidence to SRE when applicable.
  1. Ghi nhận ý định CR, source baseline, scope yêu cầu, độ khẩn cấp và acceptance criteria. ĐÃ LƯU
  2. Agent phân tích impact xuyên artifact và repository, gồm UI/UX, architecture, API, data, operations và migration.
  3. PO/PM review amendment scope; SA quyết định technical design và gate activation.
  4. Sau phê duyệt, tạo CR branch set, thực thi phần bị ảnh hưởng, tự động hóa test và deploy lên UAT.
  5. Tech Lead duyệt unit quality của Phase-Gated. PO/PM accept UAT. SA xác minh integration và promotion equivalence.
  6. Promote revision đã duyệt vào project mainstream, seal baseline mới và bàn giao bằng chứng production cho SRE khi áp dụng.
Corrections to the current approved intent loop inside the gate. New scope is a formal CR; the agent must not disguise it as a correction.
Sửa lỗi so với intent đã duyệt quay lại trong gate. Scope mới là CR chính thức; agent không được ngụy trang thành correction.
06 · HOTFIX

Restore production without losing lineage.

A hotfix starts from SRE-confirmed production composition, not an assumed mainstream head.

Khôi phục production mà không mất lineage.

Hotfix bắt đầu từ production composition do SRE xác nhận, không từ mainstream head do agent tự đoán.

Deliver HOTFIX-NN

Requirement authority: PO/PM. Technical scope: SA. PROD execution: SRE.

Delivery HOTFIX-NN

Requirement authority: PO/PM. Technical scope: SA. Thực thi PROD: SRE.

BRANCH · hotfix/HOTFIX-NN
  1. SRE confirms the exact production composition and incident boundary.
  2. PO/PM approves the bounded hotfix requirement; SA activates only the essential technical artifacts and risk controls.
  3. The agent creates the hotfix branch from confirmed production lineage, adds a regression test first, implements the fix, and produces evidence.
  4. Tech Lead reviews unit quality; SA verifies integration and operational risk; PO/PM confirms the intended business behavior.
  5. SRE performs PROD deployment. The agent records production lineage and forward-ports the fix to project mainstream.
  6. Open a postmortem or follow-up slice/CR when the minimal hotfix leaves structural work.
  1. SRE xác nhận chính xác production composition và incident boundary.
  2. PO/PM duyệt hotfix requirement có ranh giới; SA chỉ kích hoạt technical artifact và risk control thiết yếu.
  3. Agent tạo hotfix branch từ production lineage đã xác nhận, thêm regression test trước, implement fix và tạo bằng chứng.
  4. Tech Lead review unit quality; SA xác minh integration và operational risk; PO/PM xác nhận business behavior dự kiến.
  5. SRE thực hiện deploy PROD. Agent lưu production lineage và forward-port fix về project mainstream.
  6. Mở postmortem hoặc slice/CR tiếp theo nếu hotfix tối thiểu còn để lại structural work.
Never branch from an inferred production state. Never let emergency handling remove approval subjects, test evidence, or forward-port lineage.
Không tạo branch từ production state suy đoán. Xử lý khẩn cấp không được loại approval subject, test evidence hay forward-port lineage.

08 · REVIEW LOOP

Review, revise, approve—without losing the conversation.

Mandatory human gates preserve familiar working decisions.

Review, sửa, duyệt mà không mất hội thoại.

Human gate bắt buộc giữ các quyết định làm việc quen thuộc.

Complete a human gate

Accountable: authority named by the activated work-product gate.

Hoàn tất một human gate

Chịu trách nhiệm: authority được nêu bởi work-product gate đã kích hoạt.

SUBJECT · EXACT REVISION
  1. The agent submits the artifact, content digest, parent set, team revision, automated evidence, open risks, and requested decision.
  2. The human reviews using the same judgment point used in normal delivery: requirements, UI/UX, architecture, unit quality, CR, hotfix, UAT, migration, or handoff.
  3. If changes are required, the agent records feedback and answer choices, revises, re-verifies, and resubmits. Repeat until satisfied.
  4. On approval, the agent creates an immutable approval record. A mutable file label does not establish approval.
  5. Any later material change invalidates the affected approval subject and reactivates impact-driven gates.
  1. Agent nộp artifact, content digest, parent set, team revision, automated evidence, open risk và quyết định cần duyệt.
  2. Human review tại đúng điểm phán đoán của delivery thông thường: requirements, UI/UX, architecture, unit quality, CR, hotfix, UAT, migration hoặc handoff.
  3. Nếu cần sửa, agent lưu feedback và answer choice, chỉnh sửa, verify lại và nộp lại. Lặp đến khi đạt.
  4. Khi duyệt, agent tạo approval record bất biến. Nhãn file có thể sửa không tạo thành phê duyệt.
  5. Mọi thay đổi material sau đó làm mất hiệu lực approval subject bị ảnh hưởng và kích hoạt lại impact-driven gate.
Questions and user-selected answers are part of the audit trail. The agent must not summarize away a decision that changes scope, authority, or risk.
Câu hỏi và câu trả lời user đã chọn là một phần audit trail. Agent không được tóm tắt làm mất quyết định thay đổi scope, authority hoặc risk.

09 · WINDOWS + macOS

Independent machines, shared committed truth.

Developers may use macOS while PO/PM, BA, SA, Tech Lead, and other roles use Windows.

Máy độc lập, sự thật commit dùng chung.

Dev có thể dùng macOS trong khi PO/PM, BA, SA, Tech Lead và role khác dùng Windows.

Coordinate across personal PCs

Accountable: each work owner; Project SA governs technical collision.

Phối hợp qua PC cá nhân

Chịu trách nhiệm: từng work owner; Project SA quản trị xung đột kỹ thuật.

PLANE · GIT + HUB
  1. Each participant uses an independent clone. Local profiles may store name and usual role, but project authority is confirmed on join.
  2. Before work, run /kafi-aidlc-status or /kafi-aidlc-next to fetch/reconcile remote evidence and inspect current work claims.
  3. Claim bounded work by committing the claim to the Project Hub before changing shared artifacts.
  4. Use portable filenames, UTF-8, normalized line endings, atomic writes, and equivalent PowerShell/shell commands.
  5. Push without force. A rejected push or conflict triggers reconciliation and human clarification when intent is ambiguous.
  6. Regenerate derived state from canonical Markdown and immutable records; never rely on another user's local cache.
  1. Mỗi người dùng clone độc lập. Local profile có thể lưu tên và role thường dùng, nhưng project authority được xác nhận khi join.
  2. Trước khi làm việc, chạy /kafi-aidlc-status hoặc /kafi-aidlc-next để fetch/đối soát remote evidence và xem work claim hiện tại.
  3. Claim bounded work bằng cách commit claim vào Project Hub trước khi sửa shared artifact.
  4. Dùng filename portable, UTF-8, line ending chuẩn hóa, atomic write và command PowerShell/shell tương đương.
  5. Push không force. Push bị từ chối hoặc conflict kích hoạt reconciliation và human clarification khi intent mơ hồ.
  6. Regenerate derived state từ canonical Markdown và immutable record; không dựa vào local cache của người khác.
Windows/macOS differences are an automation compatibility concern, not a reason for separate methodologies.
Khác biệt Windows/macOS là vấn đề tương thích automation, không phải lý do tạo methodology riêng.
10 · MULTI-REPO

Coordinate one work identity across many repositories.

The Project Hub records contribution sets; Component Hubs own bounded delivery evidence.

Phối hợp một work identity qua nhiều repository.

Project Hub lưu contribution set; Component Hub sở hữu bằng chứng delivery có ranh giới.

Execute cross-repository work

Accountable: Project SA for shared integration; component authority for local delivery.

Thực thi work xuyên repository

Chịu trách nhiệm: Project SA cho shared integration; component authority cho local delivery.

IDENTITY · ONE ID
  1. Create one slice, CR, hotfix, cutover, or data-migration identity in the Project Hub.
  2. List affected repositories, component owners, required branches, dependencies, contract versions, and expected revision set.
  3. Claim shared artifacts before edit. Component-local artifacts remain within their Component Hub authority.
  4. The agent reconciles repository heads and contract dependencies before each component execution and before integration.
  5. For coordinated release, record CUTOVER-NN. For application data change, record DATA-MIG-NN. Neither replaces the branch model.
  6. Merge only verified and approved contributions. Record the exact cross-repository composition in the accepted baseline.
  1. Tạo một identity cho slice, CR, hotfix, cutover hoặc data migration trong Project Hub.
  2. Liệt kê repository bị ảnh hưởng, component owner, branch bắt buộc, dependency, contract version và revision set dự kiến.
  3. Claim shared artifact trước khi sửa. Artifact local của component vẫn thuộc authority của Component Hub.
  4. Agent đối soát repository head và contract dependency trước mỗi component execution và trước integration.
  5. Với release phối hợp, lưu CUTOVER-NN. Với thay đổi application data, lưu DATA-MIG-NN. Cả hai không thay thế branch model.
  6. Chỉ merge contribution đã verify và approve. Lưu chính xác cross-repository composition trong accepted baseline.
Backstage helps discover ownership and topology. Git and immutable Hub records remain the coordination and approval evidence.
Backstage giúp khám phá ownership và topology. Git và immutable Hub record vẫn là bằng chứng phối hợp và phê duyệt.
11 · MIGRATION

Let the agent migrate v0.3 through v0.9.x.

Migration is planned, evidence-preserving, resumable, and idempotent.

Để agent migrate từ v0.3 đến v0.9.x.

Migration có plan, giữ bằng chứng, resume được và idempotent.

Upgrade to v1.0

Plan/cutover approval: PO/PM. Technical mapping: SA. Execution: agent.

Nâng cấp lên v1.0

Duyệt plan/cutover: PO/PM. Technical mapping: SA. Thực thi: agent.

ID · AIDLC-MIG-NN
  1. Run /kafi-aidlc-onboarding or migration entry. The agent inventories legacy AI-DLC files offline and identifies the source version from v0.3 through v0.9.x.
  2. Read migration_help.md and the v1.0 semantic mapping. Map legacy stages, YAML/control files, documents, approvals, and Git history without deleting evidence.
  3. Write a migration plan with per-repository checkpoints, backup/recovery points, target Hub topology, activation boundary, and verification commands.
  4. PO/PM reviews, requests changes until satisfied, and approves plan and cutover. SA decides technical mapping and integration implications.
  5. The agent executes the conversion. It does not ask humans to move files manually. Each step is safe to rerun and records completion evidence.
  6. Reconcile the migrated state, produce a migration report, and activate v1.0 only at the approved boundary; in-flight work retains its original model until complete.
  1. Chạy /kafi-aidlc-onboarding hoặc migration entry. Agent inventory file AI-DLC legacy offline và xác định source version từ v0.3 đến v0.9.x.

12 · RECOVERY

Stop drift before continuing delivery.

Recovery fixes truth first, then resumes work.

Dừng drift trước khi tiếp tục delivery.

Recovery sửa sự thật trước rồi mới tiếp tục công việc.

Missing state or operating model

Run onboarding reconciliation. The agent asks the minimum guided questions and writes a PO/PM-approved conversion plan before restructuring.

Ambiguous or conflicting evidence

Apply Evidence or Ask. Present the exact conflict, sources, decision owner, and bounded choices; record the selected answer.

Git conflict or rejected push

Fetch and reconcile. Do not force-push or auto-resolve intent. Renew the work claim or ask the shared-artifact owner.

Failed quality control

Fix and re-verify. If risk acceptance is necessary, create a scoped exception with owner, expiry, compensating action, and approval.

Pre-existing Brownfield failures

Compare against the scoped Legacy Health Baseline. New regressions block; known failures remain visible and scheduled.

Approval no longer matches

Invalidate the affected subject, compute impact, reactivate gates, and seek approval for the new exact revision.

Thiếu state hoặc operating model

Chạy onboarding reconciliation. Agent hỏi tối thiểu các câu có hướng dẫn và viết conversion plan để PO/PM duyệt trước khi tái cấu trúc.

Bằng chứng mơ hồ hoặc xung đột

Áp dụng Evidence or Ask. Trình bày đúng conflict, source, decision owner và lựa chọn có ranh giới; lưu câu trả lời đã chọn.

Git conflict hoặc push bị từ chối

Fetch và reconcile. Không force-push hay tự xử lý intent. Renew work claim hoặc hỏi shared-artifact owner.

Quality control thất bại

Sửa và verify lại. Nếu cần accept risk, tạo exception có scope, owner, expiry, compensating action và approval.

Brownfield failure có sẵn

So sánh với scoped Legacy Health Baseline. Regression mới sẽ block; known failure vẫn hiển thị và được lập lịch.

Approval không còn khớp

Invalidate subject bị ảnh hưởng, tính impact, kích hoạt lại gate và xin duyệt cho exact revision mới.

  4. SRE reviews and may request changes. The project team and agent revise until SRE accepts the handoff.
  5. SRE confirms the production composition and performs PROD deployment. The agent records the returned production lineage and baseline activation evidence.
