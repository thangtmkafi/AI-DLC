What's new since v0.3

If you're still on v0.3, here's what changed across v0.4–v0.8. AI-DLC matured from a linear spec-writer into a spec-driven, test-verified, audited lifecycle — for both backend and frontend.

The four pillars (where it landed)

1 · Spec-driven · FE + BE

Every artifact derives from an upstream spec. BE from data-model.md (ENT-NN); FE from design-tokens.md + uiux-spec.md + view-model.md (MVVM). Chain: PRD → REQ → ENT → US → UNIT → TC → ADR.

2 · Docs kept up-to-date

kafi-doc-sync keeps aidlc-docs/ current with src/; Stage 14c audits doc-currency. Docs are the live contract.

3 · Audit & verifiable at each gate

Spec-conformance trace-back + Hard/Soft checklist + Stage 14c's 5 blocking sub-checks (code · tokens · UI · tests · flow). Gates verify, not rubber-stamp.

4 · Spec-driven, test-verified

QA writes test-plan + test-cases (10b); Dev generates unit test code (14b); audit checks coverage (14c). Tests are the executable spec.

Release highlights · v0.4 → v0.8

v0.4

State-file discipline + onboarding skill + ownership fixes

Stage cycle now updates aidlc-state.md after every gate (no more stale resume). Added the kafi-aidlc-onboarding skill (3 modes: setup wizard · stage detection · resume). Stage 4 ownership → PM sole; Stage 10 → SA sole.

What you do differently: run the onboarding skill on a fresh project instead of /init; resume "just works" from state file.

v0.5

PRD formalized as a Stage 4 co-deliverable

Stage 4 now produces both a PRD (product narrative · PRD-NN · what / for whom) and Requirements (REQ-NN · how the system behaves, each tracing to a parent PRD-NN). New prd.md template.

What you do differently: PM writes the PRD first, then derives REQs — no more jumping straight to technical requirements.

v0.6

HTML mockups = FE source of truth + fidelity gate

Stage 7 produces self-contained HTML mockups (design-system styled). Stage 14 must reproduce them screen-by-screen — a blocking fidelity gate. No more "the build looks nothing like the design".

What you do differently: Designer ships real HTML mockups; Dev reproduces them exactly; divergence is rejected at the gate.

v0.7

QA role + conformance audit + test workflow

New QA role. Stage 14 split into 14a (production code) / 14b (unit test code) / 14c (conformance audit). New templates: design-tokens.md, uiux-spec.md, view-model.md, data-model.md, test-plan.md, test-cases.md, dod.md. AI Review Checklist split Hard (blocking) / Soft (warning).

What you do differently: QA writes test plans + cases from specs; conformance audit blocks a unit until code/tokens/UI/tests conform.

v0.8 · this release

Layouts, code-flow, flow conformance, 14 skills, Operations

view-model gains a §6 layout sketch (Mermaid flowchart + ASCII). user-flows.md becomes Mermaid sequence diagrams; new per-unit code-flow.md. Stage 14c gains a 5th sub-check: flow conformance (code call paths match the diagrams). 14 new skills: kafi-doc-sync, kafi-verification-loop, kafi-memory, and kafi-code-review + 10 per-language reviewers (TS · Python · Go · Java · Kotlin · C++ · Rust · C# · SQL · Shell). 13 new templates (now 32 total). Operations (Stage 16/17) formalized into deployment + monitoring runbooks.

What you do differently: agents read layout from Mermaid; code is audited against declared flows; per-language reviewers run at Stage 14c; deploy + monitor are runbook-driven.

Upgrading from v0.3

You don't migrate documents. Re-install the package — the new stages, templates, and skills apply to work going forward. Your existing 00-knowledge/ and aidlc-docs/ are preserved (the installer never touches them).

# macOS / Linux
curl -fsSL https://raw.githubusercontent.com/thangtmkafi/AI-DLC/main/tools/install.sh | bash

# Windows (PowerShell)
iwr -useb https://raw.githubusercontent.com/thangtmkafi/AI-DLC/main/tools/install.ps1 -OutFile install.ps1; .\install.ps1

The installer auto-detects upgrade vs fresh install, backs up your current package files, and pulls the latest release. See the Installer Guide for flags + safety details.
