KAFI AI-DLC · WHAT CHANGES IN v1.0

From v0.3-v0.9.x to v1.0 — what breaks.

The v1 bootstrap migrates a v0.3-v0.9.x project directly; there are no staged hops. These are the changes that alter how you work:

  • Two editions become one universal release. There is no edition to choose and no per-host download. Codex, Claude Code, and Kiro read the same committed state.
  • The installer script is gone. v1.0 installs by prompt. Nothing is created, moved, backed up, or deleted until you approve an exact plan digest.
  • Nothing is relocated automatically. The v0 installer tucked existing files away on a non-empty folder. v1 lists every file it would touch in the plan you approve.
  • The fixed 17-stage lifecycle goes internal. The seventeen capabilities still exist, but the agent resolves which run from the project profile and impact. Your surface is four commands: /kafi-aidlc-onboarding, /kafi-aidlc-status, /kafi-aidlc-next, /kafi-aidlc-check.
  • Continuous becomes the default flow. Discovery and Delivery run as concurrent tracks with a Ready queue between them; Phase-Gated remains available where governance requires baselines.
  • Your root README.md is explicitly protected. It is never an install target, in v1 or in any earlier version.

Release status. The currently published release is v0.9.1. v1.0 is in preparation and is not published yet — no v1.0 download is offered anywhere.

What changed, v0.3 to v1.0.8

A history, newest first. The v0.x entries are kept because they explain how the method arrived here — they describe those releases, not the current one. Anything a v0.x entry says about blocking gates, shipped Python, or curl | bash installation was removed later, and the v1.0 entries say when.

Release highlights · v1.0

v1.0.8

Authority is a role, not a person

Separation of duties is gone: the executor-cannot-be-sole-acceptor rule, the exception-requester rule, the four-row assurance floor, and the independent-human requirement on production. Roles are accountabilities, so a person acting as SA is the SA; and the separation those rules reached for already exists, because the agent produces the work product and a human decides on it. Onboarding now asks which roles you hold as well as which one you are acting in.

What you do differently: nothing, if you were already holding several roles — that is the point. No record is marked for it and no gate waits for a second name. Documentation collapsed from ten pages to four.

v1.0.7

Joining a project that already exists

A container is rebuildable from components.md, and now there is a journey that rebuilds it. Give the agent one Project Hub repository link — with the install request, or later through onboarding — and it clones the Hub, checks the project identity, reconciles the installed release against the one the Hub records, and asks which repositories to materialize.

What you do differently: hand a new joiner the Hub link and nothing else. PMs and BAs answer "Hub only".

v1.0.6

The package ships no code, and nothing blocks the work

Every executable file and JSON schema left the installed package: what a project receives is prose, templates and two reference registries. Conformance is a prose audit the agent runs by reading, as it was from v0.3 to v0.9.1. And no finding blocks: a detector reports what it found, what would fix it, and in what order, and the work continues. Plan, approval and journal digests are gone; the SHA-256 of the downloaded release stays.

What you do differently: stop looking for a checker to put in CI — there isn't one, and there wasn't one for eleven versions. Read the Markdown plan and approve it in your own words.

v1.0.0 – v1.0.5

One core, three generated adapters, prompt-only install

Codex, Claude Code and Kiro are generated projections of one canonical methodology rather than three hand-maintained copies. Installation and upgrade run from a plain prompt against a verified public release. The Unified Project Tree replaced nested repositories: one unversioned project folder, the Hub and every component repository as sibling git roots.

What you do differently: open your agent in the project folder and paste one prompt. No installer script, no edition to choose.

Release highlights · v0.4 → v0.9.1 — history

v0.4 – v0.6

State discipline, onboarding, design-derived UI

The stage cycle began updating its state file after every gate so a session could resume without re-deriving; an onboarding skill replaced ad-hoc setup; UI work started deriving from design tokens and mockups rather than from prose.

v0.7 – v0.8

Conformance audit and per-language review

Introduced a per-unit conformance audit over code, tokens, UI fidelity, test coverage and flow conformance, and split the review checklist into hard and soft findings. At the time these blocked a unit. v1.0.6 removed the blocking outcome entirely — the audit still runs and still reports, but it never stops the work.

v0.9 – v0.9.1

The last v0 line

The final v0 releases, and the migration source the v1 bootstrap reads. A v0.3–v0.9.x project upgrades directly to v1; there are no staged hops.

Upgrading

There is no installer script any more, and you should not run one. Earlier versions of this page published curl … | bash and PowerShell one-liners. v1.0 installs by prompt: the agent resolves a verified public release, inspects your project, and shows you a plan before touching anything. Open your agent in the project folder and paste:

Use the KAFI AI-DLC Bootstrap Locator at
https://raw.githubusercontent.com/thangtmkafi/AI-DLC/main/.well-known/kafi-aidlc-bootstrap.json.
Inspect this project and the public release, then present the exact
installation or upgrade plan. Follow the bootstrap protocol from the release
being installed, not any copy already present in this project. Do not create,
update, merge, move, delete, back up, or migrate any project file until I
approve that plan. Preserve the project root README.md.

It detects a v0.x installation, classifies the folder, and asks which topology the project takes rather than inferring it. Nothing is written before you approve. Full protocol in the install and operate guide.
