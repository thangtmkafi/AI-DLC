KAFI · AI-DRIVEN DEVELOPMENT LIFECYCLE

One operating system for human-governed software delivery.

AI-DLC lets agents execute the delivery work while your team keeps judgment, authority, and approval. It adapts to the project you actually have—without losing context between stages, repositories, or people.

Choose your profileSee the workflowOpen the runbook

Một hệ điều hành cho phát triển phần mềm do con người quản trị.

AI-DLC để agent thực thi công việc phát triển, còn team giữ quyền phán đoán, thẩm quyền và phê duyệt. Quy trình thích nghi với đúng loại dự án đang có mà không làm mất context giữa các stage, repository hay người tham gia.

01 · PHILOSOPHY

Acceleration without abdication.

AI-DLC changes who performs the work, not who owns the decision.

Tăng tốc mà không từ bỏ trách nhiệm.

AI-DLC thay đổi người thực thi công việc, không thay đổi người sở hữu quyết định.

AGENT-EXECUTED

The agent does the work

Analysis, authoring, design, code, test automation, evidence, traceability, UAT preparation, and Git operations.

Agent thực thi

Phân tích, soạn tài liệu, thiết kế, sinh code, tự động hóa test, thu bằng chứng, traceability, chuẩn bị UAT và Git.

HUMAN-GOVERNED

Humans own judgment

People clarify intent, review familiar work products, request revisions, approve gates, and accept accountable risk.

Con người quản trị

Con người làm rõ ý định, review tài liệu quen thuộc, yêu cầu sửa, phê duyệt gate và chịu trách nhiệm rủi ro.

02 · PRINCIPLES

Rules that keep agents honest.

Speed is useful only when the evidence remains inspectable.

Nguyên tắc giữ agent trung thực.

Tốc độ chỉ có giá trị khi bằng chứng vẫn có thể kiểm tra.

0

Evidence or Ask

When evidence is missing, ambiguous, stale, or conflicting, the agent stops and asks. It never invents project facts.

Có bằng chứng hoặc phải hỏi

Khi bằng chứng thiếu, mơ hồ, cũ hoặc xung đột, agent dừng và hỏi. Agent không bịa dữ kiện dự án.

1

Context before action

Every stage begins with reconciliation across state, approved baselines, dependencies, decisions, Git, and Hub topology.

Context trước hành động

Mỗi stage bắt đầu bằng đối soát state, baseline đã duyệt, dependency, quyết định, Git và Hub topology.

2

Approve exact revisions

A gate binds approval to an immutable content digest, parent set, and team revision—not a mutable “approved” label.

Duyệt đúng revision

Gate gắn phê duyệt với content digest, parent set và team revision bất biến, không dựa trên nhãn “approved” có thể sửa.

3

Ask once, record forever

Questions, choices, answers, review feedback, approvals, exceptions, and revocations stay traceable.

Hỏi một lần, lưu lâu dài

Câu hỏi, lựa chọn, câu trả lời, feedback, phê duyệt, ngoại lệ và thu hồi đều được truy vết.

03 · OPERATING MODEL

Continuous by default. Phase-Gated when governance requires it.

Agile and Waterfall are friendly mappings; Continuous and Phase-Gated are the canonical operating models.

Mặc định Continuous. Phase-Gated khi governance yêu cầu.

Agile và Waterfall là cách gọi thân thiện; Continuous và Phase-Gated là tên operating model chính thức.

Chạy theo slice sẵn sàng delivery

Discovery và Delivery chạy liên tục. Mỗi slice đã duyệt dùng branch riêng và có thể tạo MVP baseline sau UAT.

Scope được khóa tại các gate quen thuộc. Scope mới đi qua Change Request, impact analysis, phê duyệt và branch cr/<id>.

04 · DUAL-TRACK

Discovery finds the next right thing. Delivery builds the current right thing.

The tracks overlap, but their authority stays explicit.

Discovery tìm việc đúng tiếp theo. Delivery xây việc đúng hiện tại.

Hai track chồng lấn thời gian nhưng thẩm quyền vẫn rõ ràng.

05 · MICRO-DLC

Every bounded change runs a complete, right-sized lifecycle.

A slice, Change Request, hotfix, migration, or design decision activates only the evidence and gates its impact requires.

Mỗi thay đổi có ranh giới chạy một lifecycle đủ nhưng vừa mức.

Slice, Change Request, hotfix, migration hay quyết định thiết kế chỉ kích hoạt bằng chứng và gate cần cho impact của nó.

06 · MULTI-HUB

One project narrative, many component delivery contexts.

Git carries the evidence. Hubs organize it. Backstage makes the topology discoverable — Software Catalog, Dependency Graph, API entities, TechDocs — as one door that reads every repository. It is not the source of truth; the Hub is.

Một câu chuyện dự án, nhiều context delivery theo component.

Git mang bằng chứng. Hub tổ chức bằng chứng. Backstage giúp khám phá topology — Software Catalog, Dependency Graph, API entity, TechDocs — như một cửa duy nhất đọc mọi repository. Nó không phải nguồn sự thật; Hub mới là.

07 · DECISION MATRIX

Configure the method from evidence, not preference.

Roles are accountabilities, not headcount.

One person may hold several roles, but each decision still has one clear authority.

Role là trách nhiệm, không phải số lượng người.

11 · SKILL COMMANDS

The agent guides the next valid move.

Users start with a small command surface; the agent reconciles state, asks bounded questions, records answers, and offers valid next actions.

Agent hướng dẫn bước hợp lệ tiếp theo.

User bắt đầu với vài lệnh chính; agent đối soát state, hỏi câu hỏi có phạm vi, lưu câu trả lời và đưa ra next action hợp lệ.

12 · INTERNAL CAPABILITIES

You never call the stages. The agent resolves them.

The seventeen capabilities are internal. Which ones run is resolved from the Project Profile and the impact of the change; you act only at the human gates. Intermediate stages use automated checkpoints, so mandatory review happens at applicable gates only.

Bạn không gọi stage. Agent tự resolve.

Mười bảy năng lực là nội bộ. Stage nào chạy được resolve từ Project Profile và impact của thay đổi; bạn chỉ hành động tại human gate. Stage trung gian dùng checkpoint tự động, nên review bắt buộc chỉ xảy ra tại gate applicable.

13 · SCENARIOS

One engine, different paths.

The method changes activation, depth, and authority—not its truthfulness.

Một engine, nhiều đường đi.

Phương pháp thay đổi activation, độ sâu và authority, không thay đổi tính trung thực.

01

Greenfield full-stack · Continuous

Discover product value, design relevant UI/API/data contracts, deliver slices, and form an MVP with user guide, API spec, operations guidance, UAT evidence, and SRE handoff.

02

Brownfield BE-only · Continuous

Reverse-engineer only the impacted boundary, establish a scoped Legacy Health Baseline, skip UI/UX, and automate regression around each slice.

03

KAFI solution · Vendor delivery

KAFI completes requirements and architecture. Vendor executes units. KAFI SA and Accepting Tech Lead govern integration and acceptance.

04

Vendor solution · Phase-Gated

Vendor performs component SA and delivery scope. KAFI Project SA protects shared architecture; new scope flows through an approved Change Request.
