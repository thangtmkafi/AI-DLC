Installer Guide

Cross-platform installer (bash + PowerShell) for setting up or upgrading AI-DLC in your project folder. Auto-detects mode, moves legacy files into 00-knowledge/references/, and downloads the latest release from GitHub.

1 · Quick start

Open your project folder in a terminal and run one command. The installer auto-detects whether you need a fresh install or an upgrade.

macOS / Linux

curl -fsSL https://raw.githubusercontent.com/thangtmkafi/AI-DLC/main/tools/install.sh | bash

Windows (PowerShell)

iwr -useb https://raw.githubusercontent.com/thangtmkafi/AI-DLC/main/tools/install.ps1 -OutFile install.ps1
.\install.ps1
Don't run /init. Both Claude Code and Kiro auto-load CLAUDE.md / AGENTS.md on every session start. /init is non-destructive (it suggests, not overwrites) but redundant on an AI-DLC project. After install, use the kafi-aidlc-onboarding skill instead — see §8.

2 · What the installer does

  1. Checks the current folder is safe (refuses if you're in $HOME, ~/Desktop, /, or C:\Users).
  2. Detects whether AI-DLC is already installed (presence of CLAUDE.md or AGENTS.md).
  3. If absent → install mode: optionally moves legacy files into 00-knowledge/references/, downloads the latest release, unzips into the current folder.
  4. If present → upgrade mode: detects current version, fetches latest from GitHub, backs up package files to .aidlc-backup-<timestamp>/, replaces them with the new version. User content (00-knowledge/, aidlc-docs/, src/, adrs/, ai-dlc/) is never touched.
  5. Prints next-step instructions.

3 · Install mode (fresh workspace)

Triggered when neither CLAUDE.md nor AGENTS.md exists in the current folder. The installer:

  1. Inventories the folder. Lists existing files, excluding .git/, node_modules/, lock files, IDE configs (see §6 exclusions list).
  2. Prompts for edition. Choose Claude Code or Kiro IDE (skip with --edition=<name>).
  3. Shows a 1-prompt summary. Lists what will be moved, downloaded, and unzipped. You approve with Y.
  4. Moves legacy files to 00-knowledge/references/ (skip with --no-move).
  5. Downloads the release zip from GitHub Releases.
  6. Unzips into the current folder. Both editions ship flat (no top-level subfolder inside the zip).
  7. Prints next-steps.

Example output (fresh install with legacy files)

=== Plan ===
  Mode:     install
  Edition:  claude-code
  Version:  v0.8
  Target:   /home/me/my-project
  Asset:    kafi-aidlc-v0.8-claude-code.zip

✓ Moved 12 item(s).
→ Downloading https://github.com/thangtmkafi/AI-DLC/releases/download/v0.8/...
→ Extracting into /home/me/my-project…
✓ Extracted AI-DLC v0.8 (claude-code).

4 · Upgrade mode (existing AI-DLC)

Triggered when CLAUDE.md or AGENTS.md exists. The installer:

  1. Parses current version from CLAUDE.md / AGENTS.md line 3 (e.g., **v0.3 · KAFI Transformation Office**).
  2. Fetches latest version from GitHub Releases API.
  3. If equal → exits with "Already on latest" (no-op).
  4. Shows a 1-prompt summary with backup path, replace list, preserve list. You approve.
  5. Backs up package files to .aidlc-backup-YYYYMMDD-HHMMSS/ in the current folder.
  6. Downloads + unzips the new release into the current folder.
  7. Prints diff suggestion (git diff to review).

What gets replaced vs preserved

EditionReplaced (backed up first)Preserved (never touched)
Claude Code CLAUDE.md, README.md, aidlc-rule-details/, .claude/ 00-knowledge/, aidlc-docs/, src/, adrs/, ai-dlc/, .git/
Kiro AGENTS.md, README.md, .kiro/ 00-knowledge/, aidlc-docs/, src/, adrs/, ai-dlc/, .git/

5 · Convert mode (Claude ↔ Kiro)

If you've been using one edition (e.g., Claude Code) and want to switch to the other (Kiro IDE) without losing your project work, use convert mode. The installer:

  1. Detects the current edition from CLAUDE.md or AGENTS.md presence.
  2. Backs up all current-edition files to .aidlc-backup-<timestamp>-from-<edition>/.
  3. Downloads + extracts the target edition (always at latest version — convert ignores --version).
  4. Preserves user content: 00-knowledge/, aidlc-docs/, src/, adrs/, ai-dlc/, .git/. These directories are edition-agnostic — both editions reference the same paths from their workflow rules.
  5. Tells you what to do with customizations: if you edited any role/skill/rule files, they live in the backup but are NOT auto-ported (the path conventions differ between editions, and Kiro adds YAML frontmatter Claude doesn't have).

Commands

Convert Claude Code → Kiro (latest)

macOS / Linux

curl -fsSL https://raw.githubusercontent.com/thangtmkafi/AI-DLC/main/tools/install.sh \
  | bash -s -- --convert-to=kiro --yes

Windows

.\install.ps1 -ConvertTo kiro -Yes

Convert Kiro → Claude Code (latest)

macOS / Linux

curl -fsSL https://raw.githubusercontent.com/thangtmkafi/AI-DLC/main/tools/install.sh \
  | bash -s -- --convert-to=claude-code --yes

Windows

.\install.ps1 -ConvertTo claude-code -Yes

What gets backed up vs replaced vs preserved

DirectionBacked up (FROM edition)Installed (TO edition)
Claude → Kiro CLAUDE.md, README.md, aidlc-rule-details/, .claude/ AGENTS.md, README.md, .kiro/
Kiro → Claude AGENTS.md, README.md, .kiro/ CLAUDE.md, README.md, aidlc-rule-details/, .claude/

Preserved both directions: 00-knowledge/, aidlc-docs/, src/, adrs/, ai-dlc/, .git/

Convert always installs the latest target version. If you pass --version=vX.Y together with --convert-to, the version flag is ignored. To downgrade and convert in one step, do them separately: convert first (lands at latest target), then run upgrade with --version=vX.Y within the new edition.

Customization migration (manual)

If you edited rule, skill, or role files in your previous edition, the conversion preserves them in the backup but does NOT auto-port them. Paths and frontmatter differ between editions:

Claude pathKiro pathFrontmatter
.claude/skills/kafi/roles/pm.md .kiro/steering/roles/pm.md Kiro adds ---\ninclusion: manual\ndescription: "..."\n--- at top
aidlc-rule-details/inception/*.md .kiro/steering/inception/*.md Kiro adds inclusion: manual frontmatter
aidlc-rule-details/common/*.md .kiro/steering/common/*.md Kiro adds inclusion: always frontmatter
aidlc-rule-details/templates/*.md .kiro/templates/*.md No frontmatter either side (templates are plain)

Diff your backup against the freshly-installed target paths to find customizations. Apply them manually with frontmatter adjusted.

6 · Flags reference

bash flagPowerShell flagDefaultEffect
--mode=<install|upgrade|convert|auto> -Mode <install|upgrade|convert|auto> auto Force a specific mode. Useful if auto-detection picks wrong.
--convert-to=<claude-code|kiro> -ConvertTo <claude-code|kiro> (unset) Switch edition. Backs up current edition, installs target edition latest version. See §5.
--edition=<claude-code|kiro> -Edition <claude-code|kiro> prompt Skip the edition prompt. Required for non-interactive (--yes).
--version=<v0.8|latest> -Version <v0.8|latest> latest Pin to a specific version. Use to install older release.
--yes -Yes false Skip the "Proceed?" confirmation. Combine with explicit edition.
--dry-run -DryRun false Print all actions without making changes. Verify plan before committing.
--no-move -NoMove false Install mode only: skip moving existing files to 00-knowledge/references/.
--help -Help false Print usage and exit.

Common flag combinations

Non-interactive install (CI / scripts)

curl -fsSL .../install.sh | bash -s -- --edition=claude-code --yes

Install older version

curl -fsSL .../install.sh | bash -s -- --edition=kiro --version=v0.3

Dry-run to preview

curl -fsSL .../install.sh | bash -s -- --dry-run

Install without moving existing files

curl -fsSL .../install.sh | bash -s -- --edition=claude-code --no-move

7 · Safety guardrails

  • Sensitive path refusal. Installer aborts if you're in $HOME, ~/Desktop, ~/Documents, /, C:\, or C:\Users.
  • Always backs up on upgrade. Existing package files move to .aidlc-backup-<timestamp>/ before replacement. Restore with mv .aidlc-backup-X/* . if needed.
  • Mixed-state detection. If both CLAUDE.md AND AGENTS.md exist (one project should not have both), installer refuses with guidance.
  • Download integrity check. Zip must be >50 KB; smaller suggests a failed download or wrong asset.
  • Idempotent reruns. Re-running on a folder already at latest version exits with "Already on latest" — no destructive change.
  • Atomic operations. Download lands in temp directory first; only moved into your folder after validation.

Exclusion list (skipped during install-mode move)

These files/folders stay in place when the installer moves legacy content into 00-knowledge/references/:

.git/             .gitignore        .gitattributes
.DS_Store         Thumbs.db         desktop.ini
node_modules/     dist/             build/         target/    .next/    .cache/
.vscode/          .idea/            .cursor/
.env              .envrc            .env.local
*.lock            package-lock.json yarn.lock      Cargo.lock
.aidlc-backup-*/  (your own backups stay put)

8 · Troubleshooting

"Refusing to install into '$HOME'"

cd into a project subdirectory first. The installer protects you from contaminating your home with AI-DLC files. Example:

mkdir ~/projects/my-treasury-app
cd ~/projects/my-treasury-app
curl -fsSL .../install.sh | bash

"Missing dependency: curl"

Install curl: brew install curl (macOS) or apt install curl (Linux).

"Download failed: github.com/..."

Verify the release exists at github.com/thangtmkafi/AI-DLC/releases. If your network blocks GitHub, contact KAFI Transformation Office for a private mirror URL.

"Both CLAUDE.md AND AGENTS.md present — mixed state"

A project should run one edition (Claude Code or Kiro), not both. Decide which to keep, rm the other, then re-run the installer.

Upgrade replaced custom changes — how to recover?

The installer backed up your prior package files to .aidlc-backup-<timestamp>/. To restore the old version:

rm -rf CLAUDE.md aidlc-rule-details/ .claude/
mv .aidlc-backup-20260525-180000/* .
rmdir .aidlc-backup-20260525-180000

Convert replaced my Claude/Kiro setup — how to revert?

The installer backed up the FROM edition files to .aidlc-backup-<timestamp>-from-<edition>/. To revert the conversion:

# Example: Claude → Kiro conversion needs reverting
rm -rf AGENTS.md README.md .kiro/
mv .aidlc-backup-20260525-220000-from-claude-code/* .
rmdir .aidlc-backup-20260525-220000-from-claude-code

User content in 00-knowledge/, aidlc-docs/, src/, adrs/, ai-dlc/ was never touched by the convert and is still intact.

"--convert-to requires an existing AI-DLC installation"

You're trying to convert a fresh folder with no AI-DLC. Convert only switches between editions of an EXISTING install. For a new project, omit --convert-to and run a plain install with --edition=kiro or --edition=claude-code.

PowerShell "execution policy" error

Windows may block running unsigned scripts. Unblock and retry:

Unblock-File -Path .\install.ps1
.\install.ps1

I want a fully manual install

Download the zip directly from GitHub Releases, unzip into your project folder, and continue with the README steps. The installer is a convenience wrapper — not required.

9 · After install — first session

Open your project folder in Claude Code or Kiro IDE. In chat, type:

Claude Code: Run #kafi-aidlc-onboarding
Kiro IDE:    #kafi-aidlc-onboarding

The onboarding skill scans your project, detects the current AI-DLC stage, loads the matching role + prompt template, and starts a session — no manual paste needed. See the Introduction or Handbook docs for the full stage → role → template mapping.

If you placed legacy files in 00-knowledge/ (BRDs, PRDs, mockups, architecture docs), the onboarding skill detects them in Mode B and routes you to the right Pre-Inception sub-flow automatically.
